Input

Campo de texto para coleta de dados do usuário. Sharp-edge, minimalista, com feedback visual preciso em cada estado de interação. Desenvolvido para o formulário de contato e orçamento — o ponto de conversão crítico do site.

07 · Validação

Validação e Feedback

Feedback imediato após o blur (quando o usuário sai do campo). Nunca validar durante a digitação — exceto contador de caracteres. Mensagens de erro devem ser específicas: explicar o problema e como corrigir.

Estado de erro — borda + ícone + mensagem
Número incompleto — use (DDD) + 9 dígitos
E-mail inválido — ex.: nome@dominio.com.br
Estado de sucesso — validação confirmada
✓ Telefone válido
/* CSS dos estados de validação */ .inp--error { border-color: var(--error); } .inp--error:focus { border-color: var(--error); box-shadow: 0 0 0 3px rgba(214,64,69,.12); } .inp-helper--error { color: var(--error); } .inp-helper--ok { color: var(--lacre); } /* ARIA obrigatório no estado de erro */ /* HTML */ <input class="inp inp--error" aria-invalid="true" aria-describedby="campo-erro" /> <span class="inp-helper inp-helper--error" id="campo-erro" role="alert">Mensagem específica do erro</span> /* JS — validar no blur, não no input */ input.addEventListener('blur', () => validate(input));

09 · Acessibilidade

Acessibilidade

Todo campo deve ter label associado via for/id. Placeholder não é label. aria-invalid e aria-describedby são obrigatórios no estado de erro.

Atributos ARIA obrigatórios
AtributoQuando usarValor
for / id Sempre — associa label ao input label[for="id"] + input[id="id"]
aria-required Campos obrigatórios "true" — em adição ao atributo nativo required
aria-invalid Estado de erro após validação "true" — remover quando corrigido
aria-describedby Sempre que há helper ou erro ID do elemento .inp-helper correspondente
aria-disabled Campo desabilitado "true" — em adição ao atributo nativo disabled
role="alert" Mensagem de erro No elemento .inp-helper--error — anuncia para leitores de tela
aria-live Helper texto dinâmico "polite" no .inp-helper estático
autocomplete Sempre nos campos do formulário name, tel, email, address-level2 conforme o tipo

10 · Diretrizes

Regras de Uso

Padrões de qualidade que garantem consistência, acessibilidade e conversão no formulário de orçamento.

Use assim ✓

  • Label sempre visível acima do campo
  • Placeholder como exemplo de formato, não como label
  • Helper text sempre presente — mesmo que vazio ocupa espaço
  • Validar no blur, não durante a digitação
  • Mensagem de erro específica: o que errou + como corrigir
  • aria-invalid + aria-describedby no estado de erro
  • Usar type semântico: tel, email, number
  • autocomplete em todos os campos do formulário
  • min-height: 48px — touch target mínimo
  • resize:vertical em textareas

Evite ✗

  • Placeholder como único label do campo
  • Validação em tempo real durante digitação
  • Mensagens genéricas: "Campo inválido"
  • Remover o campo desabilitado do DOM
  • type="text" para telefone ou e-mail
  • resize:none em textareas — limita acessibilidade
  • Campos obrigatórios sem o marcador * no label
  • border-radius acima de 4px — contradiz o sharp-edge
  • Campos sem id vinculado ao label for
  • Ícones clicáveis sem feedback visual
