Aqua DS · Componentes

Botões

Todos os botões do sistema compartilham o mesmo efeito de onda líquida no hover — um SVG de dois paths em fase oposta que sobe de baixo, criando a ilusão de superfície d'água. A onda nunca transborda graças ao overflow:hidden e ao posicionamento left:-100%; width:300%.

Prévia de todas as variantes — passe o mouse

01 · Estrutura

Anatomia

Todo botão é composto por 3 camadas sobrepostas: o container com overflow:hidden, o SVG da onda (oculto em repouso), e o label elevado via z-index. Isso garante que a onda nunca vaze para fora do botão.

/* Estrutura HTML de todo botão wave */ <button class="btn btn--md btn--primary"> <!-- Camada 1: Onda SVG (invisível em repouso, sobe no :hover) --> <svg class="wsv" viewBox="0 0 600 60" preserveAspectRatio="none"> <g class="wg1"><path class="wf1" d="M0,22 C50,6 ..."/></g> <g class="wg2"><path class="wf2" d="M0,28 C60,12 ..."/></g> </svg> <!-- Camada 2: Label (z-index: 1, sempre visível por cima da onda) --> <span class="blbl">Solicitar Orçamento</span> </button> /* CSS mínimo obrigatório */ .btn { position: relative; overflow: hidden; /* clip da onda */ isolation: isolate; /* z-index context */ } .wsv { position: absolute; left: -100%; width: 300%; /* nunca expõe borda */ opacity: 0; transition: opacity .15s; } .btn:hover .wsv { opacity: 1; } .blbl { position: relative; z-index: 1; } /* Animação da onda — bob Y only (sem translateX) */ @keyframes bob1 { 50% { transform: translateY(-14%); } } @keyframes bob2 { 50% { transform: translateY(-11%); } } .btn:hover .wg1 { animation: bob1 3.2s ease-in-out infinite; } .btn:hover .wg2 { animation: bob2 4s ease-in-out .4s infinite; }

02 · Decisão

Quando usar cada variante

Regra de ouro: uma ação principal por tela. Nunca coloque dois botões Primary lado a lado. A hierarquia visual guia o usuário — Primary → Cobalt → Outline → Ghost.

Variante
Quando usar
Primary navy-deep + sky border
A ação mais importante da página. CTA principal do hero, formulário de contato, "Solicitar Orçamento Grátis". Só deve existir um por tela. Em fundos claros e escuros.
Cobalt cobalt sólido #1A6BC4
Ação secundária de alto valor. Botão "Ver Serviços" ao lado de um Primary, segundo CTA do hero, ações de confirmação. Tem destaque próprio mas não compete com o Primary.
Outline Light branco + navy border
Ação secundária em fundo claro. "Saiba mais", "Ver todos os serviços", "Voltar" em seções com fundo branco ou névoa (#F2F6FB). Tom neutro que não distrai da ação principal.
Outline Dark navy-deep + sky border
CTA em fundos escuros (hero, seção navy). Visualmente idêntico ao Primary mas funciona como "segundo botão" quando está ao lado de um Cobalt no hero. Também usado no nav bar.
Ghost fog + mist border dashed
Ação terciária ou de navegação suave. "Ver todos →", links de paginação, ações dentro de cards que não precisam de destaque. Nunca use em posição de CTA principal.
WhatsApp #25D366
Exclusivo para links diretos ao WhatsApp. Usado no hero (CTA principal de conversão), no footer e no botão flutuante. Sempre acompanhado do ícone oficial do WhatsApp. Cor verde reconhecível dispensa explicação.

10 · Estados

Estados do Botão

Além de default e hover, o sistema define quatro estados de interação adicionais — cada um com CSS e atributos ARIA próprios que devem ser implementados em todas as variantes.

Disabled
opacity:0.35 · cursor:not-allowed · sem onda
Loading / Busy
spinner 14px · cursor:wait · aria-busy="true"
Error State
ring vermelho 2px + shake · transitório
Focus-Visible
ring duplo · visível apenas via Tab

Estado · Disabled

Disabled

Aplicado quando a ação não está disponível — campo obrigatório vazio, limite de tentativas, ou operação em andamento. A opacidade reduzida comunica indisponibilidade sem remover o elemento do layout.

Todas as variantes — estado disabled
PropriedadeValor
opacity 0.35
cursor not-allowed
pointer-events none
Onda (wsv) Oculta — display:none no estado disabled
HTML obrigatório disabled + aria-disabled="true"
Regra Nunca remover o botão do DOM — manter visível e desabilitado. Considerar tooltip explicando o motivo.
/* CSS */ .btn:disabled, .btn[aria-disabled="true"] { opacity: 0.35; cursor: not-allowed; pointer-events: none; } .btn:disabled .wsv, .btn[aria-disabled="true"] .wsv { display: none; } /* HTML */ <button class="btn btn--md btn--primary" disabled aria-disabled="true"> <span class="blbl">Solicitar Orçamento</span> </button>

Estado · Loading

Loading / Busy

Aplicado imediatamente após o clique em botões que disparam operações assíncronas — envio de formulário, chamada de API. O spinner fica inline com o texto dentro de .blbl, mantendo z-index sobre a onda SVG.

Loading em variantes principais
PropriedadeValor
cursor wait
pointer-events none
Spinner — tamanho 14×14px
Spinner — borda 2px solid rgba(255,255,255,.22) · top: currentColor
Spinner — animação spin .65s linear infinite
Texto Manter legível — "Enviando...", "Processando...", "Carregando..."
ARIA aria-busy="true" + disabled

Estado · Error

Error State

Aplicado temporariamente quando uma ação falha — envio mal-sucedido, timeout, erro de validação. Diferente do btn--danger (variante permanente de ação destrutiva), o error state é transitório: desaparece após 2–3s ou quando o usuário tenta novamente.

Error state — borda vermelha + shake (recarregue para rever a animação)
PropriedadeValor
box-shadow 0 0 0 2px #D64045, 0 0 0 5px rgba(214,64,69,.18)
animation shake .5s var(--spring) forwards
Duração 2–3s — remover a classe via JS após timeout
vs btn--danger Error state é transitório + sobrepõe qualquer variante. btn--danger é variante permanente de ação destrutiva.
ARIA role="alert" no container da mensagem de erro adjacente
/* CSS */ @keyframes shake { 0%,100% { transform: translateX(0); } 20% { transform: translateX(-5px); } 40% { transform: translateX(5px); } 60% { transform: translateX(-3px); } 80% { transform: translateX(3px); } } .btn--error-state { box-shadow: 0 0 0 2px #D64045, 0 0 0 5px rgba(214,64,69,.18); animation: shake .5s var(--spring) forwards; } /* JS — aplicar e auto-remover após 2.5s */ function setError(btn) { btn.classList.add('btn--error-state'); setTimeout(() => btn.classList.remove('btn--error-state'), 2500); }

Estado · Focus-Visible

Focus-Visible

Visível apenas na navegação por teclado (Tab / Shift+Tab) — nunca no clique com mouse. Usa box-shadow em vez de outline para respeitar o border-radius:40px do botão. WCAG 2.1 AA exige ≥3:1 de contraste do ring contra o background adjacente.

Dark variants — ring branco 2px + sky 4px
Light variants — ring névoa 2px + navy 4px
Acima é simulado — navegue com Tab para ver o ring real no browser
Grupo de variantebox-shadow
Primary · Cobalt · Outline Dark · WA · Danger · Success 0 0 0 2px #fff, 0 0 0 4px var(--sky)
Outline Light · Ghost 0 0 0 2px var(--fog), 0 0 0 4px var(--navy)
outline nativo none — box-shadow segue o border-radius do botão
Não aparece com Click de mouse — :focus-visible é nativo para navegação por teclado
WCAG AA Ring duplo de 2px + 4px garante contraste ≥3:1 contra backgrounds navy e névoa
/* Remover outline nativo em todos os estados de foco */ .btn:focus { outline: none; } /* Default (dark variants) — ring branco + sky */ .btn:focus-visible { outline: none; box-shadow: 0 0 0 2px #fff, 0 0 0 4px var(--sky); } /* Light variants override */ .btn--outline:focus-visible, .btn--ghost:focus-visible { box-shadow: 0 0 0 2px var(--fog), 0 0 0 4px var(--navy); }

12 · Diretrizes

Regras de Uso

As regras abaixo garantem consistência e hierarquia visual em todo o site.

Use assim ✓

  • Máximo 1 botão Primary por tela ou seção
  • Sempre incluir ícone WhatsApp no btn--wa
  • Hero: Large (lg) para o CTA principal
  • Nav bar: Cobalt ou Outline Dark em md
  • Cards de serviço: Ghost ou Outline Light em md
  • border-radius sempre 40px — bordas arredondadas
  • Texto sempre uppercase + letter-spacing
  • Label sempre dentro de .blbl (z-index:1)
  • SVG da onda sempre com left:-100%; width:300%

Evite ✗

  • Dois botões Primary na mesma seção
  • btn--wa fora de contexto WhatsApp
  • Botão Large (lg) fora do hero
  • Outline Light em fundo navy (invisível)
  • Ghost como único CTA de seção importante
  • Remover o efeito de onda em qualquer variante
  • Alterar o border-radius de 40px sem aprovação
  • Texto em lowercase ou sem letter-spacing
  • Botões semânticos (sucesso/erro) em CTAs de nav
